# Deployable Inventory

Read this inventory before changing runtime configuration, release workflows, or revision evidence. A successful build proves only that an artifact was built. Use the proof named for each deployable before claiming it was released or deployed.

Admin-managed settings are declared in `apps/server/internal/config/managed.go` and stored through `apps/server/internal/services/instancesettings/service.go`.                                                                                                                | Tag CI forces the full core gates for the tagged SHA and builds/scans `deploy/docker/Dockerfile` with the final version embedded, retaining its registry digest as an Actions artifact. The release workflow promotes that tested digest, deploys it, and uploads `openpost-server-*` binaries built from the tagged SHA.                                                                                                                        | The release workflow downloads the digest from successful tag CI and checks the image OCI version and revision labels. Standalone binaries embed the tag and SHA.                                                                                      |

The package SemVer is independent of the app tag. |

Keep external deployment records outside the repository. Do not put Cloudflare responses, credentials, signing material, or operator evidence in Git.

Refresh product screenshots and landing detail crops deliberately through `bun run capture:product-screenshots` when public product imagery changes, never as a release gate. The capture builds the current app and fails loudly if a product flow cannot render. Review generated images before committing; public builds copy them through the asset surface manifest.
