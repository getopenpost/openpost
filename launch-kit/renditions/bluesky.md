# Bluesky Rendition

> **Illustrative copy — not a published thread.** Include Bluesky in a real campaign only after the exact account and thread path pass the verification log.

## Post 1/5

AI can draft social posts. It should not publish them blind.

I built OpenPost as the layer between an agent and social accounts: destination-specific work, human review, and a queue you can inspect. (1/5)

## Post 2/5

The agent can inspect the selected OpenPost workspace, connected accounts, media, drafts, and schedule through MCP. It does not receive the provider credentials stored inside OpenPost. (2/5)

## Post 3/5

One base message is not pasted everywhere. OpenPost keeps account-specific renditions, so copy, media, thread shape, and settings can match each destination. (3/5)

## Post 4/5

Read-only MCP access can be limited with `mcp:read`. Creating drafts or scheduling needs `mcp:full`, and the client can require explicit approval for every execution. Review remains a human step. (4/5)

## Post 5/5

Use the Hosted service or self-host the same AGPL product as one binary or container. SQLite is the default. Redis is not required.

https://openpost.social (5/5)
