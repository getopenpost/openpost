Use the CLI from a shell, a script, CI, or an AI agent that can run terminal commands. It talks to a running OpenPost instance over HTTPS and follows the same workspace rules as the web app.

## Install

Install the npm wrapper, which fetches and verifies the matching release binary:

```sh
npm install -g @getopenpost/cli
```

You can also install the binary from [GitHub Releases](https://github.com/getopenpost/openpost/releases). Run `openpost help` or `openpost <group> <command> --help` when this guide and an installed version differ. The installed help describes that binary.

## Sign in

Use browser sign-in for an interactive shell:

```sh
openpost auth login https://app.openpo.st
```

For a headless shell, print a verification URL and code:

```sh
openpost auth login https://app.openpo.st --device
```

For CI, create a separate token and pass it through stdin:

```sh
printf '%s\n' "$OPENPOST_TOKEN" | openpost auth login https://app.openpo.st --with-token
```

Check the saved instance, identity, and workspace before a scoped action:

```sh
openpost instance diagnostics --json
openpost auth status --json
openpost workspace list --json
```

## Choose a workspace and accounts

```sh
openpost workspace use personal
openpost account list
```

Connect new social accounts in the web app at `https://app.openpo.st/settings?tab=accounts`. The CLI does not collect provider credentials.

## Create and schedule text

Use `post` for short text and threads:

```sh
openpost post create --content "Launch note" --accounts x
openpost post create --content "Launch note" --accounts x --schedule "tomorrow 2pm"
```

Use `--schedule next-slot` to choose the next available workspace slot. Inspect scheduled work with `openpost post list --status scheduled --json`.

Use `publication` for format-first content such as link shares, image posts, carousels, stories, and video. Validate before publishing:

```sh
openpost publication create --content-profile link_share --accounts company-linkedin --url https://example.com/release --content "Release notes"
openpost publication validate <publication-id> --json
openpost publication publish-now <publication-id>
```

Check `openpost provider readiness --json` before a new provider workflow. Check `openpost provider capabilities --provider <key> --json` before choosing a content profile or provider setting.

## Give the CLI to an AI agent

The `openpost-cli` agent skill teaches compatible coding assistants how to inspect context, choose the right authoring path, validate changes, and verify results. The skill does not connect to OpenPost by itself. The agent still runs the installed CLI and uses its saved profile or token.

```sh
npx skills add https://github.com/getopenpost/openpost --skill openpost-cli
```

The skill is also listed at [skills.sh/getopenpost/openpost](https://www.skills.sh/getopenpost/openpost) and published for Agent Skills discovery at [openpo.st/.well-known/agent-skills/openpost-cli.tar.gz](https://openpo.st/.well-known/agent-skills/openpost-cli.tar.gz).

Use the skill when an assistant already has terminal access. Use [MCP](/mcp) when the assistant supports MCP and you want a direct OpenPost connection without relying on shell commands.

## Verify changes

After a mutation, read the saved object and its lifecycle:

```sh
openpost publication view <publication-id> --json
openpost publication events <publication-id> --json
openpost jobs list --json
```

Do not treat `scheduled` or `queued` as `published`. For partial or failed delivery, inspect each Rendition and its lifecycle events before retrying.
