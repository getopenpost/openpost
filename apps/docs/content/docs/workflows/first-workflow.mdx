Use **Announce a GitHub release** to create a draft for each new release. You need connected destination accounts and administrator access to activate it. A private repository also needs a [GitHub connection](/workflows/connections#private-github-repositories).

## Configure and activate

1. Open **More → Workflows → Start from a template**. Choose **Use template** under **Announce a GitHub release**.
2. Open the trigger and enter `owner/repository`.
3. Open **Create draft**. Write the post, use **Insert variable** for the release title, notes, or link, and select destination accounts.
4. Keep **Review post** after the draft.
5. Open **Test data**, use the sample or **Fetch an example**, then select **Run preview**. Check the resolved post text and accounts.
6. Fix **Needs attention** warnings and select **Publish workflow**.

Publishing the workflow [activates it](/workflows/triggers#activate-or-pause). This template has no scheduling step, so it creates drafts without publishing them.

## Check the first draft

New releases are picked up on the [regular source check](/workflows/triggers#github-and-feeds); only releases after activation start runs.

After a new release appears, open **Runs**. Inspect the draft, use **Open post** to edit it, then return to the run to approve the current revision.

Schedule it from Publications, or [Schedule after review](/workflows/review-and-schedule#schedule-after-review).
