OpenPost exposes a remote [Model Context Protocol](https://modelcontextprotocol.io/) server at:

```text
https://app.openpo.st/mcp
```

An MCP client can inspect your workspaces, connected accounts, publications, schedule, media, and provider capabilities. With a full-scope connection it can also create, edit, schedule, publish, and manage other supported resources. Every private call runs as your OpenPost user and workspace.

## Choose a setup

| Client | Setup |
| --- | --- |
| Cursor | [Connect Cursor](/mcp/cursor) |
| ChatGPT | [Connect ChatGPT](/mcp/chatgpt) |
| Claude | [Connect Claude and Claude Code](/mcp/claude) |
| Other MCP client | Use the endpoint and token rules in [Tools and permissions](/mcp/tools) |

OAuth is the preferred setup for remote clients. OpenPost asks you to sign in and choose `mcp:read` or `mcp:full`, with an optional workspace binding. If the client does not support OAuth, create a developer token in **Settings → Personal → Developer** and pass it as a bearer header. Never paste that token into a prompt.

Hosted OpenPost is reachable over public HTTPS. A private self-hosted URL or `localhost` cannot be reached by a cloud client. Use the local stdio bridge instead:

```sh
openpost --profile local auth login https://your-openpost-host.example
openpost-mcp --profile local
```

The bridge keeps the connection local while the CLI handles the server session.
