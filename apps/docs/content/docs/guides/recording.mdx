Open [Recorder](https://app.openpo.st/record) to capture your screen, camera, or microphone. It saves the sources as separate synchronized files. You can also open Recorder inside [Video Editor](/guides/video-editor) and add the finished files to the current timeline together.

## Set up the capture

Select any supported combination of screen, camera, and microphone. Choose the devices you want. If a saved device is gone, Recorder tries the current default. Video options include 720p, 1080p, or 2160p and 24, 30, or 60 fps, subject to your browser and device.

For screen capture, choose a tab, window, or display in your browser's picker. Check the audio indicator after choosing: system or tab audio is present only if the browser returns an audio track. Cursor visibility also depends on the browser's capture setting.

Microphone capture can request noise suppression and automatic gain control. A countdown and planned-length estimate help you prepare and reserve local space before recording starts.

## Record and save

During capture, Recorder shows elapsed time, bytes written, free local space, and microphone level. The sources share one capture clock so the editor can place them in sync.

Chunks and a recovery manifest are written to local scratch storage while recording. Storage checks stop capture before the browser runs out of space. If a device disappears, the recorder tries the selected device and then the default. If recovery cannot continue, already flushed tracks remain available.

When you finish in the standalone Recorder, download each source file. Inside Video Editor, choose **Add to timeline** to import them as one linked edit that you can undo. **Discard** removes recoverable temporary data when possible.

## Privacy and browser limits

OpenPost requests screen, camera, or microphone access only after you start recording. Captures stay on the device unless you later upload a finished export to OpenPost. Browser permission indicators and operating-system controls remain authoritative.

Current Chrome and Edge provide the intended capture APIs. Available resolutions, frame rates, system audio, cursor options, and MIME types vary by browser, operating system, and selected device.
