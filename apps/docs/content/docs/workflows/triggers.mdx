Choose the event that should start your workflow. Use a manual trigger while you are configuring steps, or select a source for automatic runs.

## Available triggers

Choose a manual trigger, GitHub release, RSS/Atom item, interval, new post, published variant, or publishing failure. Interval triggers run every 5 minutes to every 30 days. They skip missed intervals after downtime. New-post triggers exclude posts created by automation. Failure triggers preserve recorded failures even if the post is retried before the next check.

## GitHub and feeds

GitHub and RSS/Atom sources check every five minutes. Activation records existing items as the starting point; they do not create runs. Future items start runs once each. A feed can only supply items it still retains. Catching up across many GitHub releases may take several checks.

Use an RSS/Atom trigger for one run per new article. To collect several articles on a timer, combine an interval trigger with **Read RSS feed**, as in the [feed digest example](/workflows/examples/feed-digest).

For private GitHub repositories, choose a [saved connection](/workflows/connections) with access to the intended repository.

## Intervals

An interval starts counting at activation. It does not choose a weekday or clock time. After downtime, it skips missed intervals rather than replaying every missed run.

## Activate or pause

[Preview your workflow](/workflows/testing), resolve **Needs attention** warnings, then select **Publish workflow**. Publish again after changing its draft to update future automatic runs. Existing runs retain the definition they started with.

**Pause new runs** stops automatic admission. Existing runs continue. See [run controls](/workflows/runs) to cancel remaining steps.
