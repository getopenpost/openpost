# Cross-network visibility metrics: Buffer, Postiz and TryPost

Reviewed 2026-10-29. This is a source and official-documentation review, without authenticated product sessions or live provider calls. Postiz and TryPost clean reference checkouts were fast-forwarded before inspection. Source links are pinned to the resulting revisions.

## What the comparison establishes

These products do not establish one universal meaning for “views.” In the inspected adapters, X impressions remain impressions, Threads post views remain views, and YouTube video views remain views. A shared name can therefore cover different provider events. YouTube thumbnail impressions are a separate metric: Google's Reporting API exposes `video_thumbnail_impressions` in its reach reports. Neither inspected Postiz nor TryPost YouTube adapter requests that metric. [YouTube reach reports](https://developers.google.com/youtube/reporting/v1/reports/channel_reports#reach-reports)

| Product | Observed cross-network treatment                                                                                                                                                                                               | YouTube thumbnail impressions                               |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| Buffer  | Official UI documents a Visibility chart, with selection-dependent Views/Impressions wording. Its public API keeps views, impressions and reach distinct. Exact X + Threads + YouTube addition rule remains unproven.          | Not established by the reviewed Buffer sources.             |
| Postiz  | The standard Analytics screen selects one channel. Provider-specific cards retain X Impressions versus Threads Views. Per-post YouTube exposes Views. No combined visibility counter was found in these inspected routes.      | Not requested by either inspected YouTube analytics method. |
| TryPost | Separate `views` and `impressions` totals. Threads and YouTube map to `views`; X maps to `impressions`. The default workspace summary has no visibility headline; its performance table keeps metric columns and channel rows. | Not requested by the current collector.                     |

### UI and combination rules

The Analytics route mounts `PlatformAnalytics`. That component stores one `current` channel index and passes one `currentIntegration` to `RenderAnalytics`. The renderer requests `/analytics/{integration.id}`, displays each returned `item.label` unchanged, and totals the points inside each metric series. This is aggregation within one metric for one selected channel, not a cross-network views/impressions normalization policy. The post Statistics component likewise totals each returned metric independently. [Analytics route](https://github.com/gitroomhq/postiz-app/blob/64f00fd6d0e9dfd55d202ff83983e7576e08bc2e/apps/frontend/src/app/%28app%29/%28site%29/analytics/page.tsx), [channel selection](https://github.com/gitroomhq/postiz-app/blob/64f00fd6d0e9dfd55d202ff83983e7576e08bc2e/apps/frontend/src/components/platform-analytics/platform.analytics.tsx), [renderer](https://github.com/gitroomhq/postiz-app/blob/64f00fd6d0e9dfd55d202ff83983e7576e08bc2e/apps/frontend/src/components/platform-analytics/render.analytics.tsx), [post totals](https://github.com/gitroomhq/postiz-app/blob/64f00fd6d0e9dfd55d202ff83983e7576e08bc2e/apps/frontend/src/components/launches/statistics.tsx#L61-L72)

Official Postiz documentation agrees that account analytics uses platform-supplied metric names and that per-post statistics live on the post. Its YouTube account-metric list also omits views. No cross-network audience deduplication or all-network visibility formula is established by these sources. [Postiz analytics documentation](https://docs.postiz.com/general/analytics)

### UI and combination rules

`BuildPublicationAnalyticsReport` adds `views_count` into `views` and `impressions_count` into `impressions` independently. Therefore its `views` total can add Threads post exposure and YouTube video views; X impressions remain outside that total. It retains null when no values were measured for a metric. The workspace report exposes both values separately. [publication aggregation](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/app/Actions/Analytics/BuildPublicationAnalyticsReport.php#L204-L281), [workspace projection](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/app/Actions/Analytics/BuildWorkspaceAnalyticsReport.php#L100-L118)

The default workspace summary shows Posts, Total Followers, Reactions, Comments and Eng. Rate. It does not show a combined visibility total. Performance exposes separately selectable Views and Impressions columns, with a row per channel. Both labels remain distinct in English UI copy. [summary cards](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/resources/js/components/analytics/workspace/SummaryCards.vue#L25-L70), [performance table](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/resources/js/components/analytics/workspace/PerformanceTable.vue), [metric copy](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/lang/en/analytics.php#L274-L309)

There is a mixed **exposure** measure used for engagement rate: each post selects the first measured value in **reach, then impressions, then views**. It selects one, so it does not add overlapping reach + impressions + views for the same post. Workspace engagement rate divides summed eligible engagements by summed selected exposure. This combines heterogeneous provider denominators, without establishing deduplicated people. [snapshot projection](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/app/Actions/Analytics/WritePublicationDailySnapshot.php#L133-L149), [report denominator](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/app/Actions/Analytics/BuildPublicationAnalyticsReport.php#L235-L266)

The report selects the latest daily snapshot per publication rather than adding daily lifetime snapshots. Publication identity is unique by channel key and remote post ID, and snapshots are unique by publication and date. These prevent duplicate stored observations from becoming repeated totals; they do not deduplicate viewers across posts or networks. Period filters select posts by their publication time, then use their latest saved metrics, rather than measuring only views earned during that period. [latest-snapshot query](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/app/Actions/Analytics/QueryLatestPublicationSnapshots.php), [publication uniqueness](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/database/migrations/2026_09_23_142034_create_analytics_publications_table.php#L43-L44), [snapshot uniqueness](https://github.com/trypostit/trypost/blob/cbd6244b7f9ae29326e2ed9a101c04d7d8fd81a8/database/migrations/2026_09_23_142035_create_analytics_publication_daily_snapshots_table.php#L38), [official dashboard semantics](https://docs.trypost.it/knowledge-base/insights/overview)

## Buffer

Buffer's official Insights help describes a **Visibility** chart based on impressions, with Views used for Instagram. Including Instagram in a multi-channel selection changes the summary wording to Views throughout. Networks without channel-level data are excluded with coverage notices. Post-level and channel-level availability differ: X post impressions can be available while X channel Visibility is hidden. This supports a product-level umbrella label, but does not establish the exact calculation for a selection containing X, Threads and YouTube. [Buffer Insights help](https://support.buffer.com/en-us/articles/using-insights-in-buffer-x4gLauQU5a)

The public developer guide defines views, impressions and reach separately. Its `AggregatedPostMetrics` contract returns nonbaseline metrics only when supported by every channel in the requested intersection, instead of zero-padding unsupported metrics. This API contract does not prove that the Insights headline uses the same aggregation, nor that Threads views, YouTube video views and X impressions are added into one number. No thumbnail-impressions mapping was established from these sources. [Buffer post metrics guide](https://developers.buffer.com/guides/post-metrics)

## Limits and implications

The source mappings prove what these products request and label, not approved scopes or live production delivery. They do not prove all three products handle cross-network visibility identically. Postiz mostly avoids this choice in its inspected single-channel screen; TryPost preserves separate metric keys while still combining differently defined provider views within `views`; Buffer documents an umbrella Visibility presentation but its exact provider mixture remains uncertain. None of the reviewed evidence justifies silently calling YouTube video views thumbnail impressions.
