Deploy OpenPost from Git with Coolify's [Docker Compose build pack](https://coolify.io/docs/applications/builds/docker-compose) and the supplied [`deploy/coolify/docker-compose.yml`](https://github.com/getopenpost/openpost/blob/main/deploy/coolify/docker-compose.yml). The image supports x86_64 and ARM64 servers.

## What you need

- A Coolify project and environment.
- A domain pointed at the server, such as `post.example.com`.
- Two independent [deployment secrets](/self-hosting/configuration#deployment-secrets).

## Deploy

1. Create a **Public Repository** resource with `https://github.com/getopenpost/openpost`. Use a deploy key or GitHub App for a private fork.
2. Set the build pack to **Docker Compose**, with **Base Directory** `/` and **Docker Compose Location** `deploy/coolify/docker-compose.yml`.
3. Under **Configuration → Environment Variables**, enter the [public URLs](/self-hosting/configuration#public-addresses) and [secrets](/self-hosting/configuration#deployment-secrets) with Runtime scope.
4. Set the `openpost` service domain to `https://post.example.com:8080`. The port suffix tells Coolify where to route traffic; visitors still use normal HTTPS.
5. Deploy, then verify:

```sh
curl https://post.example.com/api/v1/ready
```

Expect `"status":"ready"` and `"database":"ok"`. Check the deployment logs if it fails.

Open the app and create the first account. It becomes the instance administrator. The deployment stores SQLite and media in the `openpost_data` volume.

## Upgrade and back up

Pin the image to a release tag before production use. Back up the `openpost_data` volume and private environment settings before changing the tag and redeploying. Follow the [maintenance guide](/self-hosting/maintenance) for readiness checks and restores. Database migrations can require restoring a matching backup when rolling back.

After installation, [configure social integrations](/self-hosting/integrations) and [email delivery](/self-hosting/email) if needed.
