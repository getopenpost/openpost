Public-site delivery can retain and manually deploy a verified composed artifact instead of rebuilding during Cloudflare upload. Automatic runs retain candidates only; production cutover remains gated on operator verification.

Implementation handoff for issue #490, lane C:

- New workflow `public-site-delivery.yml` consumes successful main **push** CI runs only. It requires successful Marketing build, Documentation build and Public artifact contract jobs. Failure, skipped jobs, fork/PR runs and another source SHA fail closed. A run missing either component does not silently substitute an older artifact.
- **Required parent integration:** canonical CI must upload `public-site-input-identity-${GITHUB_SHA}-${GITHUB_RUN_ATTEMPT}` containing `identity.json` with `{ "source": "<full SHA>", "config": "<digest>" }`. Generate the digest with `bun scripts/public-site-artifact.mjs config` under the actual production build environment. Both component producers must agree on that digest. The delivery resolver uses the existing `ci-artifacts.mjs` owner. Until this sidecar exists, workflow-run consumption intentionally fails closed rather than assigning today's repository variables to yesterday's build. Bind the sidecar to the same producer run and attempt as both components when integrating rerun scheduling.
- The digest includes the public Vite PostHog values, environment, sourcemap enablement/project/UI host, and Bun/Node version declarations. Use `BUN_VERSION=1.3.11`, `NODE_VERSION=24.19.0`, `POSTHOG_UI_HOST`, and the workflow's other environment values when generating the sidecar. Source SHA binds checked-in configuration and dependency locks. No secret values enter the identity or retained manifest.
- `workflow_run` downloads the canonical outputs and composes through the existing composer. Changelog pushes, including recording commits ignored by CI, build from that exact recording SHA. Manual runs build current main. Neither path relabels pre-changelog tag bytes as the recording commit. Parent owns duplicate trigger/producer elimination and compatible component caching. The fallback currently does a complete build, so it makes no speed claim.
- Composition preserves existing redirect ordering, docs mount and agent indexes. Candidate bytes are copied and sealed **before** the existing public artifact tests rebuild components. Checks must pass before upload. The manifest stays outside the deployed directory, inventories all files including hidden discovery files, and rejects symlinks, mutations, missing/added files and identity mismatches. Canonical input identity and qualification configuration must agree.
- `public-site-qualified` retains the deployable directory and manifest for 90 days. A separate deploy job downloads and verifies that artifact again. No deployment happens on automatic triggers. Dispatch `delivery=preview` first. Dispatch `delivery=production` only after cutover approval through the `public-site-production` environment. Parent must provision environment protection rules and a least-privilege `CLOUDFLARE_API_TOKEN` repository secret plus `CLOUDFLARE_ACCOUNT_ID` variable. Missing credentials produce a configuration error. Local OAuth is never read or copied.
- Upload invokes pinned Wrangler against `openpost-marketing`, with the manifest source as `--commit-hash`, and never runs a build in the consumer. Preview uses a unique non-main branch. Production uses main. Parent must confirm that Pages' production branch is main before enabling production dispatch.
- Preview proof uses Wrangler's immutable deployment URL. Production proof uses `https://openpo.st`. Live proof compares every static file digest with eight bounded concurrent requests, including docs, changelog/feed and agent files. Pages control files are not HTTP resources and are excluded from HTTP comparison, but remain covered by the retained artifact digest. Unexpected redirects, status codes or byte transformations fail proof. The result is retained as `public-site-live-proof`.
- **Rollback:** dispatch with a successful known-good delivery `rollback_run`, its original `rollback_source` and manifest `rollback_digest`, and `delivery=preview` or `production`. It downloads that run's retained artifact without rebuilding, checks the originating workflow/main/success, expected digest, original source and current configuration identity, then re-verifies before upload and live proof. A changed configuration blocks rollback until reviewed; expired artifacts require an independently qualified rebuild. Record the successful run ID/source/digest externally before cutover. Rollback of content intentionally restores the old source, including its old changelog.
- **Remaining parent acceptance:** wire the historical producer sidecar and exact-attempt selection, resolve duplicate scheduling, provision credentials/environment restrictions, execute real preview and production deployments, run the existing `public-deployment-proof.mjs` operational proof (including Pages deployment metadata and redirect/header contracts), verify client error symbolication, demonstrate rollback, and only then decide whether to disable Cloudflare Git integration. This lane changes no remote settings and does not claim those deployment proofs have passed. Retained hash manifests establish integrity within the trusted GitHub run boundary, not independent signing or attestation.

Local acceptance: `bun test scripts/public-site-artifact.test.mjs tests/build/public-site-delivery.test.mjs`; `actionlint .github/workflows/public-site-delivery.yml`.
