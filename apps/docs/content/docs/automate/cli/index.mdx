The `openpost` CLI controls a running Hosted or self-hosted OpenPost instance. It follows the same workspace permissions and Publication lifecycle as the web app.

Use it when work starts in a terminal. For a long-running JavaScript or TypeScript service, use the [SDK](/automate/sdk). For a visual workflow, use [n8n](/automate/n8n).

## Start here

1. [Install, sign in, and choose a workspace](/automate/cli/setup)
2. [Create and publish content](/automate/cli/publishing)
3. [Run the CLI in scripts and CI](/automate/cli/scripts-and-ci)
4. [Inspect results and recover failures](/automate/cli/inspect-and-recover)

Run `openpost help` or `openpost <group> <command> --help` when this guide and an installed version differ. The installed help describes that binary.

The CLI records created Publications with the CLI creation source, so OpenPost reports them separately from web, API, SDK, MCP, and automatic posting.
