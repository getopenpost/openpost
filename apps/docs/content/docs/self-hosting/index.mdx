This guide runs one OpenPost container with SQLite and local media storage. You do not need a separate database or queue service.

## Before you start

- Install Docker with Docker Compose and keep the database and media on persistent storage.
- The published image supports `linux/amd64`. Other architectures need amd64 emulation.
- For a public instance, prepare a domain and an HTTPS reverse proxy that forwards to port `8080`. Provider callbacks and media URLs must be reachable from outside your network.

You can test locally first. Set the final public URLs before connecting social accounts.

## Install with Docker Compose

Create the data directories first:

```sh
mkdir -p openpost/data/db openpost/data/media
cd openpost
```

Create `.env` with fresh secrets:

```sh
cat > .env <<EOF
OPENPOST_APP_URL=http://localhost:8080
OPENPOST_PUBLIC_URL=http://localhost:8080
OPENPOST_MEDIA_URL=http://localhost:8080/media
OPENPOST_JWT_SECRET=$(openssl rand -base64 32)
OPENPOST_ENCRYPTION_KEY=$(openssl rand -base64 32)
EOF
chmod 600 .env
```

For a public deployment, replace all three URLs with the real HTTPS origin before connecting providers. Keep both generated secrets stable across restarts and restores.

Create `docker-compose.yml`:

```yaml
services:
  openpost:
    image: ghcr.io/getopenpost/openpost:latest
    platform: linux/amd64
    container_name: openpost
    restart: unless-stopped
    env_file: .env
    ports:
      - "8080:8080"
    volumes:
      - ./data:/data
    environment:
      OPENPOST_PORT: 8080
      OPENPOST_DATABASE_PATH: /data/db/openpost.db
      OPENPOST_MEDIA_PATH: /data/media
```

The example uses `latest`. For production, replace it with a release tag from [GitHub Releases](https://github.com/getopenpost/openpost/releases) and record that tag with your backups. Read [upgrades and backups](/self-hosting/maintenance) before changing it.

Start it and check readiness:

```sh
docker compose up -d
curl http://localhost:8080/api/v1/ready
```

Open `http://localhost:8080` and create the first account. That account becomes the instance administrator. Create a workspace, then configure the [provider integrations](/self-hosting/integrations) you need. Once a provider is configured, connect your social account and follow the [first-post guide](/guides/quickstart).

After setup, set `OPENPOST_DISABLE_REGISTRATIONS=true` in `.env` and restart if the instance should stop accepting new self-service registrations.

## Production requirements

Put the instance behind HTTPS and route the public origin to port 8080. OAuth callback URLs must match the public origin exactly. Back up `data/db`, `data/media`, and both secret values together. Configure provider apps in [configuration](/self-hosting/configuration).
