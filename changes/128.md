### Added

- Quick Cut now uses a stable multi-source model with `QuickCutSource` IDs, `File`/`FileSystemFileHandle` resolution via `probeSourceFile` and `resolveSourceFile`, and `QuickCutSegment.sourceId`. The route lets the user open multiple files in one picker, shows a source selector, and adds segments from any source. Project JSON (`quick-cut/projects/{id}.json`, version 1) persists `sources` metadata and reconnects missing files via `handles-db` (`quick-cut:{id}`) with a visible missing-source warning and safe re-add.
- Preview and segment editing switch to the segment's source: selecting a segment sets `activeSourceId`, updates `videoSrc` to that source's object URL, and seeks to the segment start. Timeline, timecode, and duration displays use the active source's metadata. Loop modes handle source switches at segment boundaries.
- Merge compatibility preflight (`preflightExport`) compares real source video/audio codec, dimensions, sample rate/channels, rotation, and container support (Mp4/WebM/Mov/Mkv) and estimates output bytes with headroom. Incompatible merges are flagged as requiring re-encode with a visible reason; quota is checked via `navigator.storage.estimate` with 15% headroom and no unsafe fallback.

### Changed

- Streaming is now truly bounded: every export path (single stream-copy, single transcode, merged stream-copy, merged transcode) writes to an OPFS `StreamTarget` scratch file. The export helpers return a `QuickCutScratchArtifact` with `scratchFile` and `discard`; only the main route copies chunkwise to the final workspace file via `openBlobWriter` (4 MiB chunks) and discards the scratch in `finally`. No `BufferTarget` is used for scalable paths and no `file.arrayBuffer()` is used to avoid O(output) memory. Per-segment temp files for merged transcode are also streaming and cleaned up on success/failure/cancel with partial final rollback.
- Export semantics corrected: removed the dummy `BlobSource` dynamic import and speculative comments; `Conversion.isValid === false` now throws `UnsupportedStreamCopyError` and is not caught to retry via transcode—fallback occurs only from an explicit `preflightExport` decision before output starts. `AbortError`, mux/write failures, and arbitrary render errors are never retried. Sequence numbers are monotonically increasing per output track across all segments (global `videoSeq`/`audioSeq`). Exact merged output retains ordered segments and removes gaps via packet-level concat or per-segment transcode with timestamp-shifted packet copy. Nearest-keyframe mode now defines snap via `findSnapKeyframe` (before/after/exact) with delta/direction surfaced in preflight and never includes outside content without a clear UI warning. Video/audio edit boundaries and encoder delay are accounted for via packet `duration` and decoder config propagation per source. Every early throw, including invalid `Conversion`, disposes its `Input` and discards scratch.
- Container/codec compatibility and decoder config changes are preserved per source; when preflight requires transcode, a consistent output encode (`avc`/`aac` in the first source's container) is forced.

### Fixed

- Multi-source file resolution, project reconnect, and preview switching no longer assume a single `File`.
- In-memory `BufferTarget` and `arrayBuffer` paths eliminated for large outputs; scratch files are chunk-copied and cleaned on cancel/failure.
- Sequence numbers no longer reset per segment in merged transcode.

### Tests

- Added `model.test.ts` for per-source overlap/normalize and `export.test.ts` for preflight codec/dimension checks.
- Added `mediabunny-fixture.svelte.test.ts` that builds two distinct generated sources (red/blue) and proves ordered A/B/A merged stream-copy: playable duration ≈3 s, packet timestamps and sequence numbers monotonic, streamed byte count matches size without `arrayBuffer`, incompatible-source preflight, and cancel cleanup.
- Added `e2e-app/quick-cut.spec.ts` for 320/390/desktop overflow and 44 px targets.

### Remaining limits

- Cross-file merges with differing frame rates are re-encoded at 30 fps; per-source FPS is not preserved in the transcode path.
- Storage estimate uses proportional file-size heuristic; exact encoded size is known only after the scratch file is finalized, but quota is checked before start with headroom.
